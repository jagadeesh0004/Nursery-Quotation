FLOW 3: RACE CONDITION SCENARIO (CURRENT - UNSAFE)
================================================================================

Thread A                        Thread B
   │                               │
   ├─ SELECT MAX(seq)=5    ├─ SELECT MAX(seq)=5
   │ (returns 5)           │ (returns 5 at same time)
   │                               │
   ├─ Calculate: 5+1=6     ├─ Calculate: 5+1=6
   │                               │
   ├─ Check GG0006 ─────────┐
   │ EXISTS=FALSE           │
   │                        │
   ├─ Insert GG0006   ├─ Check GG0006
   │                  │ EXISTS=FALSE
   │                  │
   │                  ├─ Insert GG0006 ← COLLISION!
   │                  │   (Unique constraint error)
   │                  │   ↓ FAILS
   ├─ SUCCESS        └─ RETRY (with attempt+1)
   │                     ├─ Calculate: 5+2=7
   │                     ├─ Try GG0007
   │                     └─ SUCCESS (retry worked)

RESULT: Thread A gets GG0006, Thread B gets GG0007 after retry
PROBLEM: Wastes attempts, adds latency, confusing logs


FLOW 4: RACE CONDITION FIX (PROPOSED - WITH LOCKING)
================================================================================

Thread A                              Thread B
   │                                     │
   ├─ SELECT MAX(seq) FOR UPDATE  ├─ SELECT MAX(seq) FOR UPDATE
   │ (acquires lock)              │ (waits for lock... BLOCKED)
   │                                     │
   ├─ Calculate: 5+1=6
   │
   ├─ Release lock
   │                              ├─ Lock acquired
   │                              │
   │                              ├─ SELECT returns 6 (updated)
   │                              ├─ Calculate: 6+1=7
   │                              │
   │                              ├─ Release lock
   │
   ├─ Insert GG0006       ├─ Insert GG0007
   │ SUCCESS              │ SUCCESS

RESULT: No collision, no retry needed, correct sequence
TIME: Slightly more latency due to lock waiting, but consistent
